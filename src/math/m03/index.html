Act I — The Human Story & Historical Turning Point (M.03)

The cap set problem asks for the largest set of points in F_3^n, the n-fold product of the integers modulo 3, that contains no three distinct points x, y, z with x + y + z = 0, which in this space means no line. In four dimensions the 81 points correspond to the cards of the game SET, and the largest cap there has 20 points, a result of Giuseppe Pellegrino (1970). How large a cap can be as the dimension grows stayed open for decades and is one of the well-known questions of additive combinatorics.

In Plain Words · Extra-Easy Explanation

In plain words, the cap set problem asks how many items you can put together before an unwanted pattern becomes unavoidable. Imagine choosing cards from the game SET so that no three of them form a matching trio; the more cards you choose, the harder it is to avoid one. Mathematicians wanted to know how fast that crowding effect grows as the number of dimensions increases. Questions of this kind are studied in additive combinatorics and are related to coding theory, but this folio does not claim that the results discussed here improve any real communication system.

In 2016, Ernie Croot, Vsevolod Lev and Péter Pál Pach introduced a polynomial method that bounds progression-free sets in (Z/4Z)^n (DOI DOI 10.4007/annals.2017.185.1.7 [Scite ↗]), and Jordan Ellenberg and Dion Gijswijt extended it to F_q^n, showing in particular that a cap set in F_3^n has size o(2.756^n) (Annals of Mathematics, DOI DOI 10.4007/annals.2017.185.1.8 [Scite ↗]). In December 2023, Romera-Paredes and colleagues at Google DeepMind reported FunSearch in Nature (DOI DOI 10.1038/s41586-023-06924-6 [Scite ↗]): a procedure that pairs a pretrained large language model with an evaluator, searches for programs rather than for solutions, and in dimension 8 found a cap set of 512 points, larger than the one previously known. The AlphaEvolve white paper from the same group (arXiv:2506.13131) reports a procedure for multiplying two 4×4 complex-valued matrices with 48 scalar multiplications, which it describes as the first improvement in 56 years over Strassen's algorithm in that setting.

FunSearch and AlphaEvolve are examples of combining a language model that proposes programs with an automatic evaluator that checks them. In the cap set case the evaluator can test exactly whether a proposed set contains a line, so an invalid candidate is rejected whatever the model says. The FunSearch paper also reports that the programs it finds tend to be more interpretable than raw solutions, which lets people study them. The folio does not claim that this approach carries over to other problems; that is an empirical question each case answers for itself.

Why is searching directly for a 512-point cap set inside the eight-dimensional space F_3^8 completely impossible with brute force? Because the number of candidate subsets of size 512 among the 6,561 points is the binomial coefficient C(6561, 512), about 10^779—a quantity dwarfing the 10^80 elementary particles in the observable universe. Any raw coordinate permutation search drowns instantly in combinatorial noise. FunSearch resolved this barrier by shifting search from raw coordinates into the space of executable programs (Nature, DOI DOI 10.1038/s41586-023-06924-6 [Scite ↗]). The language model evolves compact Python priority functions that evaluate each vector, while a deterministic greedy kernel selects candidate points only if they never complete an arithmetic progression x + y + z = 0 (mod 3). Separately, Ellenberg and Gijswijt established an upper ceiling via the polynomial method, bounding |S| = o(2.756^n) (Annals of Mathematics, DOI DOI 10.4007/annals.2017.185.1.8 [Scite ↗]). For comparison, the 512-point set alone gives, by taking products of copies of it, a growth rate of at least 512^(1/8) ≈ 2.181 per dimension; this is the folio's own arithmetic and not a figure from the paper.
